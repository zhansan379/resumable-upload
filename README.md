# resumable-upload · 给 AI 集成的大文件上传代码模板

**这不是一个部署了就完事的上传网站，而是一份给 AI 编码代理的代码模板**：分片上传、断点续传、秒传、完整性校验、可插拔存储（本地磁盘 / S3 兼容对象存储）全部拆成边界清晰的模块，配一份 AI 可直接执行的集成手册和 Skill——目标是让 AI 在**你的**系统里把"大文件上传"这个功能快速、正确地装好，而不是让你把业务迁进本仓库。

方案设计基于对 GitHub 高 star 开源项目的调研（uppy、blueimp、filepond、fine-uploader、plupload、resumable.js、flow.js、simple-uploader、tus、free-fs 等 10 多个项目）。

## 快速集成（两条路径）

**给 AI（推荐）**：把 [skills/resumable-upload-integration/SKILL.md](skills/resumable-upload-integration/SKILL.md) 装进你的编码代理（或直接把手册 URL 喂给它），说一句"把大文件上传集成到我的项目"。AI 会按 [docs/07-组件集成指南.md](docs/07-组件集成指南.md) 执行：

- 前置判断（Spring Boot 3.x + Java 17，不满足即停）；
- 精确到文件的复制清单（含"演示壳不要复制"的禁止项）；
- 适配点对接：API 前缀、鉴权拦截器、**租户来源**（宿主已有 JWT/SecurityContext/MyBatis-Plus 租户体系时实现一个 `TenantResolver` Bean 对接，组件不强加自己的租户头）、存储选型（local / S3）；
- **逐项验证协议**（curl 冒烟，每步有期望响应）——AI 集成不靠感觉，完成与否可机器判定。

触发示例：**把每一项按你的情况改好再发给 AI；不确定的项留空并加一句"先探索项目再问我"**。信息给得越全，AI 越少问、越少猜。

## 功能清单

- **分片上传**：文件在浏览器里切成小片（默认 5MB 一片），多片同时传（默认 3 片并发，可调到 1~6），弱网下比整文件单发更稳。
- **断点续传**：传之前先问服务器"这个文件哪些片已经有了"，已传的直接跳过。进度以服务器存储为准，服务端重启、浏览器刷新都不丢。
- **刷新恢复**：任务记录在浏览器本地持久化，刷新或重开页面后任务自动回来——正在传的任务接着传，主动暂停的任务恢复成待继续。还能记住算好的 MD5，不用重算。
- **秒传**：浏览器在后台线程算出整个文件的 MD5 发给服务器，服务器一查索引发现已经有相同内容，直接返回，一个字节都不用传。
- **暂停 / 恢复**：点暂停就中断正在传的分片；点继续时重新和服务器对齐进度，接着传缺的片。
- **失败自动重试**：网络抖动或服务器 5xx 时，分片自动按 1 秒、2 秒、3 秒退避重试 3 次；如果是 4xx 这类参数错误就直接报错，不重试浪费。
- **显式合并**：全部片传完，前端主动发一次"合并"请求，服务器按分片号顺序拼成完整文件，加锁防止同一文件被并发合并，合并前先检查分片齐不齐、总大小对不对。
- **完整性校验**：合并完成后服务器在后台重新算一遍整体 MD5 和前端给的值比对，结果在文件列表里显示"通过 / 校验中"。很多开源实现都缺这一步。
- **下载**：文件直读直发不占内存。支持 HTTP Range 断点下载，浏览器和 IDM 这类下载工具可以接着下、多线程加速。
- **文件管理**：文件列表、下载、删除；点取消上传会把服务器上的分片临时目录一并清理。
- **存储可插拔**：默认本地磁盘零依赖开箱即跑；改一行配置切换 S3 兼容对象存储（MinIO / RustFS / 阿里 OSS / 腾讯 COS / 华为 OBS 等，S3 协议一个实现通吃），协议层与前端无感。
- **多实例部署**：元数据进宿主数据库（**MyBatis / MyBatis-Plus 双实现，按宿主类路径自动探测**，没库则回落 JSON 文件），合并互斥自动升级为数据库租约锁；配合对象存储即可水平扩展。
- **多租户**：租户来源可插拔——默认读请求头，宿主已有租户体系（JWT / SecurityContext / MP TenantLineHandler）时实现一个 `TenantResolver` Bean 对接；秒传 / 下载 / 删除 / 列表按租户分域，字符集校验防路径注入。
- **预签名直传（可选）**：S3 后端开启后，浏览器直传对象存储、服务端零带宽转发；服务端只管签发分片地址、秒传判定与合并，客户端无需回传 ETag。
- **前端组件化（复制即用）**：headless 调度核心与 UI 解耦——核心 4 文件任何框架可用；Vue3 附带零 UI 库依赖的 `<UploadPanel>` 面板组件（拖拽/进度/暂停恢复/刷新恢复开箱即用，样式整段可换）。与前件一样由 AI 复制集成，不发 npm 包。

## 测试与验证

一句话版：**功能测试 0 错误、性能瓶颈在家里上行带宽而不是服务端、默认参数就是最优、传一半杀进程/磁盘塞满都能恢复、极弱网下传统整文件上传永远传不完而分片可以**。

| 测试项 | 大白话结果 |
|--------|-----------|
| 功能全链路（JMeter 7 组） | 176 个请求 0 错误，本机回环和公网各跑一遍都通过 |
| 性能 | 公网传 100MB 约 21 秒，已经顶满家里上行带宽；本地回环测试证明服务端代码不是瓶颈 |
| 参数扫描 | 分片改成 2/10/20MB、并发开到 6，都不比默认的 5MB/并发 3 更快——默认参数就是最优工作点 |
| 边界文件与合并风暴 | 0 字节、超限、刚好卡在上限的文件全部正确处理；1000 个文件同时传也扛得住，内存零泄漏 |
| 对抗性中断 | 传一半杀进程、磁盘塞满、OOM 注入都能恢复；过程中发现并修复了一个残缺文件入库的真 bug |
| 弱网注入与基线对比 | 极端弱网下传统整文件上传永远传不完，分片上传配合自动降并发能完成——这个能力已实现在前端 |

图表与原始数据在 [docs/images/](docs/images)，**完整用例、注入方法、逐项数据与复现步骤见 [docs/06-测试报告.md](docs/06-测试报告.md)**。

除 JMeter 之外，仓库自带 **8 个 JUnit 集成测试套件、41 个用例**（本地磁盘 / MinIO / RustFS 容器 / MyBatis / MyBatis-Plus / auto 探测 / 租户隔离 / 宿主租户源接管），跑同一套协议用例——`mvn test` 即可回归，也是 AI 集成后验证"行为没被改坏"的基准。
