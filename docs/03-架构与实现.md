# 架构与实现

> 返回 [README](../README.md)

## 架构与上传流程

```
Vue 3 前端                                Spring Boot 后端
──────────────                            ──────────────────
1. spark-md5 Worker 计算整文件 MD5   ─┐
                                     │
2. POST /api/upload/check ───────────┼──>  hash 索引命中？ ── 是 ──> 返回 finished=true（秒传）
                                     │         │ 否
                                     │         └──> 扫描分片目录返回 uploadedChunks
3. 并发上传分片（并发3，失败重试）    │
   POST /api/upload/chunk ───────────┼──> 临时文件 + 原子移动 -> chunks/{fileHash}/{i}.part
4. 全片完成 POST /api/upload/merge ──┼──> 校验分片齐全/总字节 -> FileChannel 顺序合并
                                     │         -> files/{yyyyMM}/{hash}_{name}
                                     │         -> 写 hash 索引 -> 删分片目录
                                     │         -> 后台重算 MD5 校验（异步）
5. 展示进度 / 速度 / 状态            ─┘
```

存储布局（local 后端，`UPLOAD_DIR` 指向的目录，默认 `./data/upload`）：

```
data/upload/
├── chunks/{fileHash}/{chunkIndex}.part   # 分片临时目录（0 起编号）
├── files/{yyyyMM}/{fileHash}_{fileName}  # 合并后的最终文件
└── index.json                            # hash 索引（秒传依据，服务重启不丢）
```

## 存储分层（SPI）

存储动作全部经由接口委托：协议层（`UploadController`/`UploadService`）不含任何本地文件概念，
切换存储后端不影响 HTTP 协议与前端。接口定义在 `store/spi/`，
本地实现在 `store/local/`，S3 兼容实现在 `store/s3/`（AWS SDK v2，一个 `S3UploadStorage` 同时实现两个存储 SPI）：

| SPI 接口 | 职责 | local 实现 | S3 兼容实现 |
|----------|------|------------|-------------|
| `ChunkStorage` | 分片写入 / 枚举（含单片大小）/ 清理 / 孤儿清理 | `{index}.part` 临时文件 + 原子移动；按目录 mtime TTL 清理 | uploadPart（懒建会话）/ ListParts / abortMultipartUpload；过期上传会话清理 |
| `FileStorage` | 合并产物固化 / 存在性 / 读取（全量 + Range）/ 删除 / 容量水位 | FileChannel 顺序拼接；locator = 相对路径；磁盘可用空间 | completeMultipartUpload；locator = 对象 key（`{keyPrefix}/{fileHash}`）；GetObject + Range 头；无容量概念（返回 0 跳过水位检查） |
| `MetadataStore` | 秒传索引（租户 + fileHash → FileRecord） | `index.json`（临时文件 + 原子替换） | **MyBatis / MyBatis-Plus**（宿主关系库，多实例共享；type=auto 按类路径探测） |
| `MergeLock` | 合并互斥（分片校验 + 固化 + 索引写入关键区） | JVM 监视器锁（单实例语义） | 数据库租约锁（MyBatis 注解 Mapper，TTL 60s + 过期接管，多实例互斥） |
| `UploadEventListener` | 合并完成 / MD5 复核结论 / 删除 事件回调 | 无内置实现，集成方按需订阅 | 同左 |
| `TenantResolver` | 租户来源（默认读 `tenant.header` 请求头，可被宿主 Bean 覆盖以对接 JWT/SecurityContext 等已有租户体系） | HeaderTenantResolver | 同左（与存储后端无关） |

切换开关：`app.upload.storage.type: local | s3`（s3 配置示例见 application.yml）；
元数据：`app.upload.metadata.type: json | mybatis | mybatis-plus | auto`（默认 auto：类路径有 MyBatis-Plus 用之，
其次 MyBatis，均无回落 json；显式 mybatis 系但缺依赖会启动失败并给出提示；auto 探测到 MyBatis 系时要求宿主已配置数据源）。
S3 端点兼容 MinIO / RustFS / AWS S3 / 阿里 OSS / 腾讯 COS / 华为 OBS 等一切 S3 协议服务。
**租户隔离**：`app.upload.tenant.header` 配置请求头名即启用（默认关闭）；启用后秒传/删除/下载/列表按租户分域，
存储层收到 `{tenant}/{hash}` 作用域 ID（本地嵌套目录、S3 嵌套 key），租户标识限定 `[A-Za-z0-9._-]{1,64}` 杜绝路径注入。
**预签名直传**：`app.upload.storage.s3.direct-upload: true` 时装配 `POST /upload/direct/init`（秒传判定 + 建会话）
与 `POST /upload/direct/part-urls`（批量签发分片直传地址），浏览器 PUT 直传对象存储后复用既有 merge（服务端 ListParts
自取 ETag）；前端直传适配器规划中，当前后端能力已由 MinIO 端到端测试覆盖。
设计约定：

- **locator 是后端私有地址**（本地 = 相对路径，S3 = 对象 key），协议层只透传、不解析、不拼接；
- 分片写入必须**幂等**（弱网重复发送以后到者为准），`list` 只返回确认完整的分片（"半片"不可见）；
- S3 硬约束通过能力声明由协议层前置收紧：除末片外单片 ≥ 5MiB（`ChunkStorage.minNonLastPartSize`）、
  multipart 上限 10000 片（`ChunkStorage.maxChunks`）；multipart ETag 不是 MD5，
  合并后复核仍按整体读回计算（对象存储下有读回流量成本，可用 `verify-md5-after-merge=false` 关闭）；
- S3 的 multipart 会话状态（uploadId）**不落本地**：按 key 从 ListMultipartUploads 反查，
  与"存储端为事实源"一致，天然支持多实例；
- 磁盘专属逻辑不出现在协议层：水位检查读取 `FileStorage.usableBytes()`（≤0 视为不适用即跳过），
  残缺文件恢复、空目录清理等全部内聚在 local 实现。

集成测试三后端跑同一套协议用例（`AbstractUploadBackendTest`）：`LocalStorageBackendTest`（本地磁盘）、
`S3BackendTest`（MinIO）与 `RustFSBackendTest`（RustFS，横向验证其 S3 兼容层）两个容器后端；
容器套件额外覆盖非末片 ≥ 5MiB 前置拒绝与取消上传中止会话语义（`AbstractS3ContainerBackendTest`）。

### 云端对象存储配置示例（S3 兼容端点）

| 服务商 | endpoint | region | path-style-access |
|--------|----------|--------|-------------------|
| 阿里云 OSS | `https://oss-cn-hangzhou.aliyuncs.com` | `oss-cn-hangzhou` | false |
| 腾讯云 COS | `https://cos.ap-guangzhou.myqcloud.com` | `ap-guangzhou` | false |
| 华为云 OBS | `https://obs.cn-north-4.huaweicloud.com` | `cn-north-4` | false |
| AWS S3 | 留空（SDK 默认端点） | 如 `us-east-1` | false |
| MinIO / RustFS 自建 | `http://<host>:9000` | 任意（`us-east-1`） | **true** |

```yaml
app:
  upload:
    storage:
      type: s3
      s3:
        endpoint: https://oss-cn-hangzhou.aliyuncs.com   # 阿里云 OSS 示例
        region: oss-cn-hangzhou
        bucket: your-bucket
        access-key: ${OSS_ACCESS_KEY_ID}                 # 密钥走环境变量，不要进仓库
        secret-key: ${OSS_ACCESS_KEY_SECRET}
        key-prefix: files
        path-style-access: false
```

注意事项：

- **凭证最小权限**：云厂商使用子账号（RAM / CAM / IAM），只授予目标 bucket 的对象读写与 Multipart 操作权限，密钥走环境变量或密管系统；
- **path-style-access**：自建 MinIO/RustFS 必须 `true`；云厂商一般 `false`（虚拟主机风格，桶名会进入域名，需符合各家桶命名规则），若遇 DNS/签名报错再切换验证；
- **配额差异**：各云厂商对分片数、单片大小、并发上传会话数有独立配额（与 AWS S3 默认值不同），上线前建议用 S3BackendTest 同款用例对目标账号跑一遍冒烟；
- **后端代理模式无 CORS 顾虑**：本组件默认由服务端中转分片，浏览器不直连对象存储；若后续启用预签名直传模式，需另行配置桶的 CORS 规则。

## API 一览

| 方法 | 路径 | 说明 |
|------|------|------|
| POST | `/api/upload/check` | 秒传 + 断点探测。入参 `{fileHash, fileName, totalSize, totalChunks, chunkSize}`；返回 `{finished, uploadedChunks, url, ...}` |
| POST | `/api/upload/chunk` | 上传单个分片（multipart：`fileHash/chunkIndex/totalChunks/chunkSize/totalSize/fileName/chunk`） |
| POST | `/api/upload/merge` | 合并请求，入参同 check；分片缺失返回 409 |
| GET | `/api/files` | 已上传文件列表 |
| GET | `/api/files/{fileHash}/download` | 下载；支持 Range 断点续传：200 全量 / **206 区间**（`Content-Range: bytes start-end/total`）/ 416 超界 / `ETag`=fileHash + `If-Range` 条件请求（不匹配回退 200 全量） |
| DELETE | `/api/files/{fileHash}` | 删除文件及索引 |
| DELETE | `/api/upload/{fileHash}` | 取消上传，清理分片目录 |

错误码语义（参考 tus 协议）：`400` 参数非法 / `409` 分片缺失、状态冲突 / `413` 超过大小上限 / `415` 分片超限 / `500` 服务端错误。前端仅对网络错误与 5xx 重试，4xx 直接失败。

## 关键实现

**前端（`frontend/src/`）**

- `upload/md5Worker.js`：spark-md5 在 Web Worker 中按 2MB 分片增量计算整文件 MD5，带进度，不撑爆内存；
- `upload/uploader.js`：调度器。并发工作循环（默认 3）从待传队列取分片；AbortController 支持暂停/取消；4xx 永久错误与可重试错误分类（uppy 的 retryDelays 思想）；全片完成调合并端点（fine-uploader success.endpoint 思想）；
- `App.vue`：拖拽上传、任务表（进度/速度/状态）、服务器文件管理。

**后端（`backend/src/main/java/com/example/upload/`）**

- `service/UploadService.java`：协议编排层。参数校验、`fileHash` 粒度锁防并发合并、合并前分片齐全性与总字节校验、后台单线程重算 MD5（弥补多数开源实现缺失的完整性校验）、生命周期事件广播；所有存储动作委托给 SPI，自身无文件系统概念；
- `store/spi/`：存储抽象——`ChunkStorage`（分片）、`FileStorage`（合并产物 + ContentHandle 读取）、`MetadataStore`（秒传索引）、`UploadEventListener`（事件）；语义按对象存储 multipart 模型设计，详见上文「存储分层」；
- `store/local/`：本地磁盘实现（`LocalStorageConfig` 按 `app.upload.storage.type=local` 装配）。分片写入「临时文件 + 原子移动」杜绝半片、合并按分片号顺序 `FileChannel.transferTo` 追加（兼容乱序到达）、自带残缺文件恢复路径；`store/JsonMetadataStore.java`：hash 索引持久化到 `index.json`，秒传依据与服务端重启恢复；
- `controller/UploadController.java`：协议端点；下载支持 **Range 断点续传**（`HttpRange` 解析 + `ContentHandle.readRange` 定位读流返回 206，`ETag`=fileHash 配合 `If-Range`，416/非法 Range/多区间各有明确语义）；`exception/GlobalExceptionHandler.java`：统一错误码。
