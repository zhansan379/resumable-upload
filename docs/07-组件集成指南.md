# 组件集成指南（复制即用 · 人与 AI 通用）

> 返回 [README](../README.md)。本文档面向"把本组件复制进自己的系统"的集成者，按步骤执行即可完成集成。
> **AI 执行约定**：这是给 AI 编码代理的集成手册——按顺序执行，遇前置不满足立即停止并报告，
> 禁止修改协议字段名（`fileHash/chunkIndex/totalChunks/totalSize` 的语义与拼装格式），
> 完成后必须执行第 6 节验证协议并向用户汇报逐项结果。
> 源码锚定版本：`main` 分支 commit `97c150c`（集成前先确认你拿到的是该版本或更新，见第 8 节）。

## 1. 前置判断（不满足就停下）

| 检查项 | 要求 | 不满足时的处理 |
|--------|------|----------------|
| 宿主后端 | Spring Boot 3.x + Java 17+ | 停止并告知用户：组件依赖 jakarta 命名空间与 Spring 6 |
| 前端 | 任意框架或纯 HTML | 核心无框架依赖（仅 axios + spark-md5），无需停 |
| 端口/路径 | 宿主没有 `/api/upload/**`、`/api/files/**` 冲突路由 | 有冲突则改用 `app.upload.api-prefix`（见 5.2） |
| 存储介质 | 本地磁盘（默认）或 S3 兼容对象存储 | S3 需要可用 endpoint + 凭证 + 桶（自建 MinIO/RustFS 或云厂商） |

**宿主主类必须补两个注解**（最常见的集成失败原因）：

```java
@SpringBootApplication
@ConfigurationPropertiesScan   // 缺了它 UploadProperties 不绑定，全部配置静默失效
@EnableScheduling              // 缺了它孤儿分片定时清理不运行
public class YourApplication { ... }
```

依赖：local 后端零额外依赖；S3 后端加 `software.amazon.awssdk:s3` + `apache-client`（2.55.x，见本仓库 pom）；
元数据用 MyBatis 系时加 `mybatis-spring-boot-starter` 或 `mybatis-plus-spring-boot3-starter`（本仓库标记为 optional，宿主按需引入）。

## 3. 集成步骤（后端）

1. 复制第 2 节清单中的后端文件到宿主源码树；
2. **包名重命名**：`com.example.upload` → 宿主包（如 `com.yourco.upload`）。单条命令（在源码根执行）：
   ```bash
   grep -rl "com.example.upload" <目标目录> | xargs sed -i 's/com\.example\.upload/com.yourco.upload/g'
   ```
3. 宿主主类补 `@ConfigurationPropertiesScan` + `@EnableScheduling`（见上）；
4. 按第 5 节完成配置与适配；
5. S3 后端：额外复制 `store/s3/`、加 SDK 依赖、配置 `app.upload.storage.type=s3`（示例见 [03-架构与实现.md](03-架构与实现.md) 云端配置小节）。

## 4. 集成步骤（前端）

1. 复制 4 个前端文件，装依赖：`npm i axios spark-md5`；
2. 若 API 前缀不是 `/api`：页面加载前设置 `window.__UPLOAD_API_PREFIX__ = '/你的前缀'`（须与后端一致）；
3. 对接方式：参照 `frontend/src/App.vue`——创建 uploader 实例 → 监听进度/速度/完成事件 → 渲染你自己的 UI。

## 5. 适配点

### 5.1 配置项一览（`app.upload.*`）

| 配置 | 默认值 | 说明 |
|------|--------|------|
| `api-prefix` | `/api` | REST 挂载前缀，同时决定响应里的下载 URL 前缀 |
| `base-dir` | `./data/upload` | local 后端：分片/最终文件/index.json 根目录 |
| `storage.type` | `local` | `local` \| `s3` |
| `storage.s3.*` | — | endpoint/region/bucket/access-key/secret-key/key-prefix/path-style-access |
| `storage.s3.direct-upload` | `false` | 开启预签名直传端点（见 5.5） |
| `metadata.type` | `auto` | `json` \| `mybatis` \| `mybatis-plus` \| `auto`（按类路径探测，MP 优先） |
| `tenant.header` | 空 | 配置请求头名即启用租户隔离（见 5.4） |
| `verify-md5-after-merge` | `true` | 合并后整体读回复核 MD5；对象存储下有读回流量成本，可关 |
| `max-total-size` | `20GB` | 单文件上限 |
| `max-total-chunks` | `100000` | 单文件分片数上限（S3 后端自动收紧为 10000） |
| `chunk-ttl` | `24h` | 孤儿分片清理阈值 |
| `spring.servlet.multipart.max-file-size` | `20MB`（Boot） | 单分片上传上限，须大于前端单片大小 |

元数据多实例说明：宿主类路径有 MyBatis-Plus / MyBatis 且配置了 `spring.datasource.*` 时，
`auto` 自动选用之（秒传索引进库 + 数据库租约合并锁，多实例可水平扩展）；
不打算用库请显式 `metadata.type: json`（单实例语义）。表结构（upload_file_record / upload_file_lock）启动时自动创建。

### 5.2 API 前缀

改后端：`app.upload.api-prefix: /files-api`（控制器挂载与响应内下载 URL 同步变化）。
改前端：`window.__UPLOAD_API_PREFIX__ = '/files-api'`。

### 5.3 鉴权接线（必须做，组件不做鉴权）

组件的写操作（上传/删除/取消）默认匿名。在宿主的 WebMvcConfigurer 里挂拦截器：

```java
@Override
public void addInterceptors(InterceptorRegistry registry) {
    registry.addInterceptor(authInterceptor)
            .addPathPatterns(apiPrefix + "/upload/**", apiPrefix + "/files/**");  // 写读都要拦
}
```

### 5.4 多用户/多租户（务必阅读）

- **启用租户**：`app.upload.tenant.header: X-Tenant-Id`（头名自定）。启用后每个请求必须携带该头，
  缺失或非法（允许 `[A-Za-z0-9._-]{1,64}`，防路径注入）直接 400；
  秒传命中、文件列表、下载、删除全部按租户分域——跨租户同名内容互不可见、不可删；
- **不启用时 fileHash 是全局索引键**：不同用户传相同内容会互相秒传，删除按 hash 全局生效。
  单用户或内部系统可接受；多用户系统强烈建议启用租户头，另在拦截器里校验操作者与租户的归属关系；
- **秒传探测面**：同一租户内，知道文件 hash 即可探测"是否已有此文件"。敏感场景对 check 接口收紧鉴权；
- **多实例部署**：`metadata.type` 选 mybatis/mybatis-plus（元数据进宿主库）+ 存储用 S3 系 + 合并锁自动升级为
  数据库租约锁，即可水平扩展。local 磁盘存储永远单实例。

### 5.5 预签名直传（可选，仅 S3 后端）

`s3.direct-upload: true` 开启两个端点：

1. `POST {prefix}/upload/direct/init`：秒传判定 + 创建/复用 multipart 会话，返回 uploadId、
   已传分片（断点续传）、非末片最小字节数；
2. `POST {prefix}/upload/direct/part-urls`：按批次签发分片直传地址，浏览器/客户端 PUT 直达对象存储（服务端零带宽）；
3. 全部传完后**复用既有** `POST {prefix}/upload/merge`（服务端 ListParts 自取全部 ETag 后 complete，客户端无需回传 ETag），
   取消复用 `DELETE {prefix}/upload/{hash}`。

注意事项：init/part-urls 等价于"授权写入对应对象"，必须纳入宿主鉴权；浏览器直传需在对象存储桶上配置 CORS
（允许宿主页面的 Origin、PUT 方法、ETag 响应头）；前端直传适配器规划中，当前可自行在 uploader 的分片发送处
切换为 PUT 预签名地址。

### 5.6 业务事件

实现 `UploadEventListener`（onMergeCompleted / onVerifyCompleted / onDeleted）注册为 Spring Bean，
即可在文件落库、通知、统计等环节挂钩；单个监听器抛异常不影响上传主流程。

## 6. 验证协议（集成完成必须全跑）

```bash
BASE=http://localhost:8080/api          # 换成你的前缀
head -c 5242880 /dev/urandom > /tmp/c0  # 非末片 5MiB（S3 后端硬性要求；local 不要求）
head -c 5242880 /dev/urandom > /tmp/c1
head -c 100 /dev/urandom > /tmp/c2
cat /tmp/c0 /tmp/c1 /tmp/c2 > /tmp/full
HASH=$(md5sum /tmp/full | cut -d' ' -f1); SIZE=$(stat -c%s /tmp/full)

# ① check → 期望 {"finished":false,"uploadedChunks":[]}
curl -s -X POST $BASE/upload/check -H 'Content-Type: application/json' \
  -d "{\"fileHash\":\"$HASH\",\"fileName\":\"it.bin\",\"totalSize\":$SIZE,\"totalChunks\":3,\"chunkSize\":5242880}"
# ② 三片上传 → 各返回 {"chunkIndex":i,"size":5242880|100}
curl -s -F fileHash=$HASH -F chunkIndex=0 -F totalChunks=3 -F chunk=@/tmp/c0 $BASE/upload/chunk
curl -s -F fileHash=$HASH -F chunkIndex=1 -F totalChunks=3 -F chunk=@/tmp/c1 $BASE/upload/chunk
curl -s -F fileHash=$HASH -F chunkIndex=2 -F totalChunks=3 -F chunk=@/tmp/c2 $BASE/upload/chunk
# ③ 合并 → 期望 {"fileHash":"$HASH",...,"size":$SIZE,"verified":false}
curl -s -X POST $BASE/upload/merge -H 'Content-Type: application/json' \
  -d "{\"fileHash\":\"$HASH\",\"fileName\":\"it.bin\",\"totalSize\":$SIZE,\"totalChunks\":3,\"chunkSize\":5242880}"
# ④ 再 check → 期望 finished:true（秒传）
# ⑤ 全量下载 MD5 比对 → 必须与 $HASH 一致
curl -s $BASE/files/$HASH/download | md5sum
# ⑥ Range → 期望 206 且 Content-Range: bytes 0-99/$SIZE
curl -s -D - -o /dev/null -H "Range: bytes=0-99" $BASE/files/$HASH/download | grep -E "HTTP|Content-Range"
# ⑦ 删除 → 期望 {"deleted":true}；再下载 → 期望 404
curl -s -X DELETE $BASE/files/$HASH
```

全部符合 → 集成成功。任何一步不符 → 对照第 7 节排障，修完重跑全链。

## 7. 故障表

| 症状 | 原因 | 处置 |
|------|------|------|
| 配置改了不生效（仍写默认目录） | 宿主主类缺 `@ConfigurationPropertiesScan` | 补注解（见第 3 节） |
| 孤儿分片永不清算 | 缺 `@EnableScheduling` | 补注解 |
| 上传报 413 | Boot multipart 上限小于单片 | 调大 `spring.servlet.multipart.max-file-size` |
| S3 模式保存分片 400"非末片分片至少 5242880" | 前端单片 < 5MiB | 前端 chunkSize 调大到 5MiB（末片豁免） |
| S3 AccessDenied | 子账号缺 multipart 权限（ListMultipartUploads 等） | 按最小权限清单补齐 |
| Windows 下目录异常 | baseDir 反斜杠/盘符问题 | 用正斜杠：`D:/data/upload` |
| 前端跨域被拦 | 前后端分离部署 | 后端加 CORS 配置（同源/单容器部署无此问题） |
| 删除接口任何人可调 | 未接鉴权（5.3） | 挂拦截器 |
| 多实例下秒传/列表不一致 | JSON 元数据是单实例语义 | 等 JDBC 实现或暂锁单实例 |

## 8. 版本锚定与升级

- 集成时记录所用源码的 commit hash（本文锚定 `97c150c`，之后以仓库最新为准）；
- 组件协议（check/chunk/merge 的字段）与错误码语义为兼容性承诺，升级只增不改；
- 升级后复跑第 6 节验证协议；本仓库 `backend/src/test/` 的 16 个双后端用例是上游回归的基准。
